Kee Route Manager watches VPN nodes, maintains a working Xray pool and gives you a place to control routing on your own gateway.

01 / Overview

Built for day-to-day routing.

Subscriptions

Manage supported VLESS links and Xray JSON node lists. Keep provider headers in private storage.

Health checks

Compare independent VPN and WAN probes. Uncertain results leave the active route alone.

Pool and failover

Score candidates, maintain an Xray hot pool and switch deliberately when evidence is sufficient.

Local control

A web panel, command-line tools, diagnostics and signed updates with explicit approval.

02 / Architecture

A small set of separate tools.

The UI does not own routing state or firewall rules.

  • kee-route-managerd Controller, scheduler, Xray and platform state.
  • kee-route-manager-ui Independent web panel and API proxy.
  • kee-route-managerctl Local administration and validation.
  • kee-route-manager-launcher Signed update slots and supervised startup.

03 / Get started

Start with a signed release.

The installer expects a working Xray setup. Choose the bootstrap for your platform from a fixed release, review the runbook and back up your current configuration first.

curl --proto '=https' -fsSLo /tmp/krm-bootstrap.sh \
  https://github.com/jarymor-ux/kee-route-manager/releases/download/v1.3.3/bootstrap-linux.sh
sh /tmp/krm-bootstrap.sh

Example for Linux only. On Keenetic or OpenWrt, use the matching bootstrap asset from the same release. Do not pipe an unverified script to a shell; follow the signature-verification instructions.

04 / Scope

What to expect.

KRM currently manages Xray, not arbitrary VPN backends or AmneziaWG. Hardware qualification is incomplete across all supported platforms. In particular, Keenetic does not have automatic direct bypass when Xray stops entirely.

Updates are signed and explicitly applied; the launcher and some platform configurations still require separate maintenance. Keep device backups and a recovery path.
