01 / Overview

Built for day-to-day routing.

Subscriptions

Manage supported VLESS links and Xray JSON node lists. Keep provider headers in private storage.

Health checks

Compare independent VPN and WAN probes. Uncertain results leave the active route alone.

Pool and failover

Score candidates, maintain an Xray hot pool and switch deliberately when evidence is sufficient.

Local control

A web panel, command-line tools, diagnostics and signed updates with explicit approval.

02 / Architecture

A small set of separate tools.

The UI does not own routing state or firewall rules.

  • kee-route-managerd Controller, scheduler, Xray and platform state.
  • kee-route-manager-ui Independent web panel and API proxy.
  • kee-route-managerctl Local administration and validation.
  • kee-route-manager-launcher Signed update slots and supervised startup.

03 / Get started

Start with a signed release.

Signed v2.0.1 uses Go 1.27.3, including the GO-2026-6809 crypto/x509 fix. Upgrade older generated Keenetic configurations offline before installation. Legacy v1.3.3 uses affected Go 1.27.2 and remains immutable. The v2.0.0 tag failed CI and has no release assets. Hardware acceptance is still pending for individual models.

Read the mandatory upgrade migration ↗

First prepare compatible stock firmware, Entware, storage and a working XKeen/Xray setup on the router. KRM does not install these prerequisites. Review the runbook and keep private backups plus an independent recovery connection.

curl --proto '=https' -fsSLo /tmp/krm-bootstrap.sh \
  https://github.com/jarymor-ux/kee-route-manager/releases/download/v2.0.1/bootstrap-keenetic.sh

Keenetic/Netcraze example pinned to signed v2.0.1. Its bootstrap verifies Ed25519 signatures and SHA-256 before downloaded programs execute. Verify initial bootstrap trust too. MIPS Big Endian binaries are included; KN-2410/2510 still require physical-device acceptance.

Before execution: obtain the v2.0.1 SHA256SUMS and SHA256SUMS.sig, verify the Ed25519 signature with the release public key authenticated independently, then check this file against the signed bootstrap-keenetic.sh digest. Stop on any missing file, mismatch or unknown key. Follow the trust-verification runbook below; a public key downloaded beside the signature is not independent trust.

Only after the signature and bootstrap digest are verified, run:

sh /tmp/krm-bootstrap.sh

04 / Scope

What to expect.

Router targets are Keenetic and Netcraze with compatible stock firmware, Entware and Xray. Hardware qualification is incomplete for individual models. Keenetic/Netcraze has no automatic direct bypass when the main Xray process stops.

KRM uses the Xray backend only. Signed updates require explicit application; the stable launcher and remote management UI need separate maintenance. Keep backups and a recovery path. Version 2.0.1 includes MIPS Big Endian soft-float builds; a model name or cross-build does not establish physical-device compatibility.

Check the exact model and its resources

Inspect the full model index, native ABI and byte order, available RAM, Entware storage and working Xray configuration. A 256 MB router shares memory with firmware and VPN traffic; there is no guaranteed 256 MB capacity claim. Core-only and a remote management UI can reduce resident processes on the router.

Will KRM install Entware or Xray?

No. Set up these prerequisites separately and prove your existing client route before installing KRM.

Can I put the UI on another computer?

Yes, as a management-only client over an authenticated SSH tunnel with verified upstream TLS. The sole routing controller stays on the Keenetic/Netcraze router.

Does v2.0.1 support KN-2410?

Version 2.0.1 includes signed MIPS Big Endian binaries and read-only resource/dependency preflight. KN-2410 hardware acceptance remains pending: measure KeeneticOS, Xray and KRM peaks, prove the client route and retain recovery access. Never substitute a little-endian binary.
