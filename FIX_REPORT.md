## Границы и восстановление

Сохранены sole-owner daemon/locks, CLI client-only, независимый UI dependency graph, journal-before-effects, capability-gated platform bypass. Benchmark не включает direct; неопределённый WAN/target evidence сохраняет route. `update.apply` остаётся disabled. Keenetic fail-open capability не добавлена.

Не выполнялись deployment, публикация, изменение production router/SSH/WAN policy/credentials или host firewall/install/uninstall. Linux интеграция использует readonly source mount, отдельную копию внутри `--rm --network none` контейнера; только nft tests получают NET_ADMIN. Installer fixture использует настоящий installer и binaries, но fake service manager и unconfigured routing. Container kernel/nft успех не доказывает Keenetic/OpenWrt hardware, real Xray API, configured production restore или kill-9/power-loss acceptance.

Локальная проверка повторяется командами из receipts/таблицы. Установка на устройство — отдельная задача по [AGENT_INSTALL.md](docs/AGENT_INSTALL.md), без mutable releases и с private backup/independent recovery path. Для ambiguous legacy journal или owner сохраните private journal/config/runtime dump вне Git и сравните фактические resources с ожидаемыми; не удаляйте journal и не дописывайте ownership priority вслепую. Точный identity или отсутствие старого policy rule позволяют последующую безопасную reconciliation; неизвестные effects требуют операторского решения.
